# 全站性能修复验证记录

## 范围与方法

基线提交 `58ed1bb`，对比本批工作区修复。环境为 Apple M4 Pro、Node.js 26、PostgreSQL 16 和 Next.js 生产构建。仅使用隔离数据库与本地服务，没有访问生产数据库或部署。

合成数据包含 3,000 篇约 32 KB 正文、30,000 条媒体、10,000 条图库记录、3,000 条文章评论、500 首歌曲及约 1,000,000 条访问日志。普通接口预热后采样 20 次，日志接口采样 10 次。原始测量保存在 `/tmp/tano-blog-performance-audit/`；本文件保存主要结果，避免临时目录清理后丢失结论。测试期间补充的少量创建、上传和访问记录不会用于冒充严格相同数据集的微小差异。

## 结果

响应大小为未压缩 JSON；分页后的数字表示首批数据，后续条目仍可继续读取。

### 日志、取消与上传

- 统计默认近 30 天，所有图表共用聚合结果和 15 秒缓存。缓存命中统计 p50 约 0.8–1.6 ms；覆盖约百万记录的 91 天冷聚合一次约 **3.17 秒**。旧统计范围和新接口返回内容不同，不能将缓存数字解释成等范围冷查询提升。
- 游标后续页约 **1.5–3.7 ms**。默认范围下第 20,000 页已超出末页，修复后 p50 **14.46 ms**；旧全历史页不是相同查询范围。执行计划验证：移除对约 32.9 万行的窗口排序与临时文件，越界只计数一次。
- 不存在路径筛选最终 p50 **1.41 ms**。中间复测曾为 245.78 ms，随后 PostgreSQL 自动维护后 GIN 查询恢复亚毫秒；不能把全部差异归因于本批代码。
- 搜索请求约 140 ms 时取消；约 331 ms 起连续五次检查均没有遗留活动文章查询。
- 声明 100 MiB 的无效上传经 Next 在客户端发送约 3 MiB 后即返回 400，采样 Node RSS 增量约 **33 MiB**，基线约 **163 MiB**。这是单次资源探测，不是内存上限承诺。独立传输集成测试另验证有效 100 MiB 请求完整穿过 Next 流式路由及取消传播。
- 大备份测试将 **269.1 MiB JSON / 28,000 条记录**完整导出并恢复，约 **8.56 秒**，采样峰值 Go HeapAlloc **35.2 MiB**；堆分配不等于进程 RSS。

## 功能与回归

- 前端 **81/81** 行为测试通过，TypeScript、生产构建通过；ESLint **0 errors / 463 warnings**。警告主要为既有 `any`、原生图片与 hooks 规则，未进行无关的全局样式清理。
- `TEST_DATABASE_DSN=... go test ./... -count=1`、`go vet ./...`、后端构建通过。数据库测试覆盖迁移、分页、取消、访问控制、备份回滚、评论父引用恢复、通知落库和异常日志批次。
- 原生 Edge 验证：匿名正文与评论加载更多、登录、新文章代码块/公式、图片粘贴自动上传、单图 50% 宽度、文章保存、媒体缩略图、播放器跨公共页面持续播放、日志使用游标翻页。
- 浏览器验证发现并修复代码块预览崩溃：`pre: undefined` 改为原生 `pre`；真实组件测试先复现错误，再验证修复。
- 创建文章现在自动生成 UUID 预览令牌。真实 Next → Go → PostgreSQL 连续创建草稿与发布文章均返回 201，两个预览均返回正确文章。旧唯一索引迁移、新库、幂等迁移、历史链接保留和非空令牌唯一性均有回归。
- 独立复核发现的通知取消、超长日志、备份文件一致性、评论跨批次父引用和管理详情缺少关联问题已修复并验证。

部署参数、容量限制、取消行为及升级迁移说明见 [性能与容量运维指南](performance-operations.md)。本记录代表本地验证，生产负载下仍应观察请求耗时、连接池等待与日志丢弃计数。
