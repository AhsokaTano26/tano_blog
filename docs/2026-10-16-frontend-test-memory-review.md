# 前端测试内存事故复核与修复

## 结论与证据边界

2026-10-16 的证据高度支持以下链路：React/JSDOM 元素断言失败 → Node
生成巨大的对象描述和差异 → 未结束的测试被重复启动 → 系统资源耗尽。
缺少事发时单个 Node PID 的内存快照或调用栈，因此这是强证据支持的归因，
不能称为完全确证，也不能据此彻底排除其他唤醒问题。

独立复核使用 `~/Library/Logs/MacWakeCheck-20261016/` 中的时间线、内存记录、
源码副本及受限探针结果。`manifest.sha256` 的 11 个文件均校验通过；本轮没有
重新运行历史危险断言，也没有执行其高内存差异算法。

| 时间（北京时间） | 证据及解释 |
| --- | --- |
| 13:43:36–13:44:26 | Terminal 资源组内存记账由 4.79 GiB 增至 79.25 GiB，其他主要应用基本稳定。资源组记账不等于实际常驻 RAM。 |
| 13:44:02、13:44:17 | 同一回归测试连续启动，两次均只输出前两项失败，未见完成记录。 |
| 第三项测试 | `assert.equal(button('加载更多'), undefined)` 在按钮仍存在时失败，把带 React 内部引用的 DOM 元素交给错误格式化。 |
| 13:44:33 起 | 应用挂起、压缩内存不足、WindowServer 和电源服务超时。磁盘仍有约 57.7 GiB 空闲；未找到对应 kernel panic。 |

本机 Node 26.0.0 的内嵌 `assertion_error`、`myers_diff` 源码与保存副本的 SHA-256
一致。检查确认：对象展开深度为 1000；Myers 差异每层复制并保留完整 Int32Array。
已有深度 10 探针记录了 238,919 行；仅用整数计算复核，与单行 `undefined` 比较
可能需要约 425.30 GiB 的差异追踪数组。这是理论估算，**没有实际分配或测得该峰值**。
相关实现见 [Node 26.0.0 AssertionError 源码](https://raw.githubusercontent.com/nodejs/node/v26.0.0/lib/internal/assert/assertion_error.js)。

## 修复与加固

- 保留前一轮 4 个测试文件中 15 处布尔比较，补齐 `home-performance.test.js`
  的 1 处遗漏。仍检查原来的存在性、空值或元素身份，失败信息只接收基本类型。
- 保留首次渲染前注册 React 清理的修复；新增真实挂载按钮的安全失败测试，验证
  错误信息短于 256 字符，且不读取 DOM 上的检查哨兵属性。
- 加固独立 Python watchdog：同一用户各工作树共用互斥锁；记录进程组以阻止
  守护进程异常终止后的重复启动；限制可透传的 Node 选项。
- 信号处理只记录退出请求，避免中断启动与清理；先终止进程组再检查监控权限，
  等待并确认清理完成后才清除记录。正常退出也清理残留子进程。
- 默认串行、每个 Node old-space 512 MiB、Node 超时 30 秒、外部截止时间 120 秒、
  进程组采样阈值 1536 MiB；同时检查墙钟与单调时钟，禁用 core dump。
- 保护机制自测使用有限时间、有限内存的探针；有独立清理，并让内层守护进程
  继承全局锁，防止外层自测被终止后另一批测试立即进入。

macOS 使用包含压缩页的 `phys_footprint`，Linux 使用进程组 RSS 总和。
约 100 ms 的采样**不是操作系统硬配额**；V8 堆限制也不覆盖所有原生内存。
主动脱离进程组的子进程、守护进程 SIGKILL、系统整体停顿仍有保护边界。
需要硬上限时应使用设有内存、swap、PID 限额的 Linux cgroup/container。
具体入口、退出码和限制见 [前端测试指南](../frontend/TESTING.md)。
