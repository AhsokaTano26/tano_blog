# 后台 UI/UX 改进与验证（2026-10-19）

## 本轮范围

围绕日常写作和管理调整概览、文章列表、编辑器、附件页与后台导航。保留现有主题、API 和编辑数据流程，未添加依赖。概览突出写作入口和待审核事项；文章默认显示核心列，可展开完整信息；编辑器提供明确的编辑、分屏、预览选项，手机使用单栏；附件提供可见操作和语义化预览按钮。

## 浏览器检查

使用本地隔离 Demo 与 Safari 原生界面，响应式视口分别为 320×640、390×844、768×1024、1440×900，并检查了浅色和深色主题。已验证概览进入新建编辑器并返回、手机编辑与预览切换、移动导航打开及 Escape 关闭、侧栏收起，以及附件类型筛选和清除后的空状态。

首轮检查后修正并复核：

- 新建入口过早清除 URL 意图，鉴权刷新重挂载后返回列表：改为关闭编辑器时清除，并新增生命周期回归测试。
- 表格编辑按钮、分页标签换行，以及手机文章标题被状态挤压：操作不换行，手机标题独占一行。
- 热门文章面板被图表撑高形成大片留白：根据自身内容确定高度。

附件操作不再依赖悬停，预览入口使用按钮，支持键盘激活。已使用用户在 Demo 中选择的约 2 MB PNG 图片完成失败重试、上传成功、刷新后持久显示、缩略图及原图预览的浏览器验证。复核后补齐附件分页标签不换行、窄屏分页换行和预览关闭按钮的无障碍名称。未进行实体手机、屏幕阅读器或跨浏览器测试。

## 本地 Demo 上传故障

重启演示前端时遗漏运行时 `API_UPSTREAM_URL`，导致普通请求使用构建时的正确代理地址，而独立的上传流式接口回退至本机 8080 端口，误连其他服务并显示“禁止跨站修改”。已以 `API_UPSTREAM_URL=http://127.0.0.1:18080` 重启前端，原失败文件重试后显示“已上传 1/1 个文件”。这是 Demo 启动配置遗漏，未修改生产上传接口。后续启动 standalone 前端时，应在构建与运行两个阶段保持 API 地址一致。
