# 后台全页面精修

## 方向与边界

用户要求优化后台所有页面。默认选择保留现有玻璃质感、主题色及深浅模式，统一工作台的排版和操作体验；这是实现方的默认选择。可选的极简重设计或强化莱茵生命视觉会扩大变更，因此本轮不采用。进入动画、接口权限和数据行为保持现有契约。

覆盖全部 23 个后台路由（含概览、19 个管理页面和 3 个认证页面）。不改公开前台，不增加依赖，不提交或推送。验证只用独立的无界面浏览器和临时服务，不控制用户窗口，结束后关闭本轮服务。

## 页面规范

- 共用页头：保留原有标题及操作按钮，添加具体用途说明；宽屏左右排列，窄屏自然换行。
- 管理区使用统一的宽度、间距、面板、边框、文字与焦点样式；浅色模式的辅助信息保持可读。
- 所有表格在自己的容器滚动，长内容可换行，操作按钮保持可见；不隐藏业务列或数据。
- 设置、资料、备份、音乐馆等分页导航有清楚的选中状态，窄屏可横向滚动。
- 日历和通知使用主题语义色，移除重复外边距；日历在窄屏保留完整七列并在内部滚动。
- 分类、标签等内联表单提供持续可见的字段名称，登录和密码表单有可关联标签、状态提示和一致的认证容器。
- 导航保留现有路由，增加当前页面上下文与键盘跳至内容入口；不重建有未保存输入的页面。

## 验证

复用现有 JSDOM 回归，对新增键盘入口、认证表单可访问名称、选中导航状态添加必要行为测试。用独立 headless Chromium/WebKit 检查全部路由的明暗主题和宽窄屏，至少核对 320、390、768、1280、1440 宽度；记录横向溢出、页面错误及截图。最后运行完整测试、lint 和生产构建。
