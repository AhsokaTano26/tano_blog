# 编辑器草稿与并发保存

编辑器在停止输入 700 毫秒后保留本地草稿，持续输入时最多间隔 5 秒写入；页面隐藏、离开和组件关闭时也会尝试保存。界面区分正在保存、已保留和存储失败，并提供重试。存储受限时应优先保存到服务器。

每个编辑窗口使用独立的 `post_autosave_<文章 ID 或 new>:<随机 ID>`，新文章也不会互相覆盖。重新打开编辑器可选择恢复的草稿；旧版单一键仍可读取。成功保存仅清理当前窗口，以及内容仍与恢复时完全一致的来源草稿，保留其他窗口后续修改。

草稿保存在当前浏览器的 localStorage，不会自动同步到其他设备，也不会替代服务端备份。密码不会写入草稿；涉及新密码的恢复需要重新输入。浏览器清理站点数据会删除草稿。

## 冲突处理

后台编辑、文章设置和历史版本恢复提交 `expected_updated_at`，值为读取文章时服务器返回的完整时间字符串。服务器在文章行锁事务内核对版本，同时保存正文、关联和历史记录；版本不匹配返回 HTTP 409：

```json
{ "code": "post_conflict", "error": "文章已在其他窗口更新，请比较后再保存", "current_post": {} }
```

冲突时本地内容保持不变。用户比较服务器快照后，可加载服务器版本，或明确选择保留本地并重新提交；若此时服务器再次变化，仍会再次提示冲突。提交过程中继续输入的内容会保留，已确认的保存内容成为新的比较基线。

系列成员增删与排序也推进受影响文章的版本。生成预览链接只轮换预览令牌，不改变正文版本。旧 API 客户端不传 `expected_updated_at` 仍可保存，但无法获得乐观并发保护；新客户端应始终传入。

## 离开保护

关闭编辑器及站内链接会提示未保存的修改；刷新或关闭标签页使用浏览器原生离开提示。App Router 页面在有修改时添加同地址历史保护项，浏览器返回会先保存草稿，存储失败则要求明确确认。此机制可能截断编辑前的“前进”分支；意外卸载后可能留下一个同地址历史项，不篡改 Next.js 原有历史状态。

真实浏览器回归与资源限制见 [浏览器测试说明](browser-tests.md)。本地存储属于尽力保护，不能抵御断电、操作系统强杀或人为清除数据。
